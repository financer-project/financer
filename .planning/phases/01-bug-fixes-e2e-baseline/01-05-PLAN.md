The listener logs the error and returns `false`. Cypress treats an `uncaught:exception` as handled the moment ANY registered listener returns `false`, so this one call neutralises the global handler for the remainder of this test.
- **The global handler it neutralises.** `test/cypress/support/e2e.ts:104-106` registers `Cypress.on("uncaught:exception", ...)` returning `!err.message.includes("DYNAMIC_SERVER_USAGE") && !err.message.includes("Minified React error #419")`. Those two allow-listed messages are the entire allowlist and must stay exactly two.
- **The fix, already written.** 01-REVIEW.md's CR-01 "Fix" section gives the target shape: capture the error into a variable inside the listener, keep the diagnostic log, keep `return false` so the remaining assertions still run, and assert the variable is `undefined` at the end of the test with the captured message in the assertion's message argument.
- **Why `return false` stays.** Removing it would abort the test at the moment of the exception and lose the remaining filter assertions. The goal is a test that still runs to completion and then fails loudly with the real stack trace attached — not one that dies early.
- **realPress types available in the installed package.** `node_modules/cypress-real-events/commands/realPress.d.ts` exports `RealPressOptions` and declares (but does not export) `type Key = keyof typeof keyCodeDefinitions`; `node_modules/cypress-real-events/keyCodeDefinitions.d.ts` exports `keyCodeDefinitions` as a `declare const` with 264 keys. Because `Key` itself is not exported, the project must re-derive it from `keyCodeDefinitions`. `tsconfig.json` uses `moduleResolution: "node"`, so deep subpath type imports resolve by file path.
- **Existing realPress call sites all type-check under the tighter union.** `test/cypress/e2e/formKeyboardNavigation.spec.ts` uses only `"Tab"`, `"Shift"`, `"Enter"`, `"Escape"` and the `as const` array `["Enter", "Space", "ArrowDown"]` (line 174) — all confirmed present in `keyCodeDefinitions`.
