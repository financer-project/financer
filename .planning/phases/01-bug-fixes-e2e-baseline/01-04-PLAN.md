- **Coverage comparison inputs:** the merge job produces one `.test/lcov.info` via `yarn coverage:merge` (`lcov-result-merger ".test/**/*.info" .test/lcov.info`). LCOV line coverage is `LH / LF`; the "Before" section records both raw totals, so the comparison must be done on `LF` and `LH` rather than on a rounded percentage — a percentage can round two genuinely different coverage levels to the same figure.
- **Shard-count ceiling:** the shard count must stay at or below the E2E spec file count, because a shard that receives zero specs fails rather than passing vacuously. RESEARCH.md expects diminishing returns past roughly four to six shards for this suite's size, driven by per-shard runner startup and Testcontainers boot cost.
- **Non-negotiable guard rails (PITFALLS.md Pitfall 8):** `retries.runMode` stays at 2 and every `after()` / `after:run` cleanup stays in place. These are not speed levers — cutting them trades a real performance win for CI flake and cross-spec data contamination.
- **Run inspection commands:** `gh run list --branch <branch> --workflow "CI Workflow" --limit N --json databaseId,conclusion,createdAt,updatedAt,url`, `gh run view <run-id>`, `gh run download <run-id>`, and `gh run rerun <run-id>` for repeat runs.
- **Attributing the improvement:** the workflow total now includes parallel job groups, so the honest comparison is against the same measure recorded in "Before" — record both the total workflow duration and the E2E stage duration (the slowest shard, since shards run in parallel and the stage is only as fast as its slowest member).
</interface_context>
