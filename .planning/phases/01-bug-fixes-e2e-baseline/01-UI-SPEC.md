### Interaction Order Contract (the load-bearing contract for this phase)

Elements: `select-field-trigger` (`SelectField.tsx`, used by Account/Type/Category/Counterparty/Tags `SelectFormField` instances in `TransactionForm.tsx`), `date-picker-trigger` (`DatePicker.tsx`).

| # | Truth | Status | Source |
|---|-------|--------|--------|
| 1 | Tab order through `TransactionForm.tsx` matches standard DOM/visual order, top-to-bottom left-to-right — no custom `tabIndex` scheme | ✅ covered | D-04 |
| 2 | Every `SelectField` trigger (Account, Type, Category, Counterparty, Tags) is reachable via Tab — fix is scoped to the specific `InputGroup` instance rendered inside `SelectField.tsx`'s `PopoverTrigger`, not to `InputGroup`'s shared defaults (which are also used by unrelated, already-focusable search inputs elsewhere) | ✅ covered | RESEARCH.md Pitfall 2, root-cause trace |
| 3 | Once a `SelectField` trigger receives focus (via Tab or click), `Enter`/`Space`/`ArrowDown` opens the popover — focusable-but-inert is not an acceptable fix | ✅ covered | RESEARCH.md Pitfall 2 |
| 4 | Shift+Tab retraces the **exact reverse** of the forward Tab path (not merely "no traps") | ✅ covered | D-06 |
| 5 | `DatePicker.tsx`'s trigger is Tab-reachable and its click/open behavior is unaffected by the fix (its wrapping `<div>` also gets Radix's cloned `aria-*`/`onClick` via `asChild`, same pattern as the affected `SelectField`, but wraps a real `<Button>` which is natively focusable) | ⚠ unresolved | RESEARCH.md A3 / Open Question 2 — static analysis suggests low risk, but D-05 explicitly requires on-browser/Cypress confirmation of the whole form including the date field; planner must include an explicit verification step, not assume A3 |
| 6 | The fix does not globally change `InputGroup`'s default focusability — plain (already-focusable, `<input>`-containing) search fields elsewhere (e.g. `TableToolbar.tsx`) are unaffected | ✅ covered | RESEARCH.md Pitfall 2 scoping requirement |

Regression test tooling: `cy.realPress('Tab')` / `cy.realPress(['shift','Tab'])` via `cypress-real-events` (not synthetic `keydown` simulation) is required to assert truths 1–4 and verify truth 5, per RESEARCH.md's Don't-Hand-Roll guidance — a synthetic-event test could pass while the real native tab order stays broken.
